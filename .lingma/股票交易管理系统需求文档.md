# 股票交易管理系统需求文档

## 一、项目概述

### 1.1 项目名称
股票交易管理系统（Stock Trading Management System）

### 1.2 技术栈
- **后端框架**: FastAPI
- **数据库**: SQLite (SQLAlchemy ORM)
- **前端**: HTML + Tailwind CSS + Vanilla JavaScript
- **部署**: Docker + Docker Compose

### 1.3 核心功能
实现一个完整的股票/基金交易记录管理系统，支持买卖操作、持仓管理、盈亏计算等功能。

---

## 二、数据模型设计

### 2.1 交易记录表 (stock_trades)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Integer | 主键，自增 |
| buy_order_no | String | 买入单号（唯一索引），格式：NO + YYYYMMDD + 4位流水号。买入时生成，卖出时关联对应的买入单号 |
| contract | String | 合约代码（如：512690），有索引 |
| name | String | 合约名称（如：酒ETF） |
| price | Float | 交易价格 |
| shares | Integer | 交易份额（买入为正数，卖出为负数） |
| remaining_shares | Integer | 剩余可卖份额（仅买入记录有效） |
| amount | Float | 成交金额（price × shares） |
| fee | Float | 手续费（max(amount × fee_rate, min_fee)） |
| net_amount | Float | 净额（amount + fee） |
| trade_type | String | 交易类型：buy（买入）/ sell（卖出） |
| trade_date | String | 交易日期（YYYY-MM-DD格式） |
| created_at | DateTime | 创建时间 |
| realized_profit | Float | 累计已实现收益（仅买入记录，累加所有关联卖出的收益） |
| single_profit | Float | 单笔收益（仅卖出记录，记录该笔卖出的收益） |

### 2.2 持仓表 (stock_positions)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Integer | 主键，自增 |
| contract | String | 合约代码，唯一索引 |
| name | String | 合约名称 |
| total_shares | Integer | 总持仓份额（= 总买入份额 - 总卖出份额） |
| avg_cost | Float | 平均成本价（= (总买入金额 - 总卖出金额) / 持仓） |
| latest_price | Float | 最新价格（最后一笔交易的价格） |
| market_value | Float | 市值（total_shares × latest_price） |
| profit | Float | **收益**（所有卖出记录的 single_profit 汇总，已实现收益） |
| profit_rate | Float | **收益率**（未实现盈亏 / 净成本 × 100%） |

### 2.3 流水号计数器表 (daily_serial_counters)

**设计说明**: 采用方案A独立计数器表，确保买入单号的全局唯一性和连续性。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Integer | 主键，自增 |
| counter_date | String | 日期（YYYYMMDD格式），唯一索引 |
| current_serial | Integer | 当前流水号（每天从1开始递增） |

**使用规则**:
- 每次创建买入记录时，根据交易日期查询或创建计数器记录
- 如果当天已有计数器记录，current_serial + 1
- 如果是新的一天，创建新记录，current_serial = 1
- 买入单号格式：`NO{YYYYMMDD}{流水号:04d}`（例如：NO2024010100001）

## 三、核心业务逻辑

### 3.1 买入逻辑

#### 3.1.1 新增买入交易
**触发条件**: `shares > 0`

**处理流程**:
1. **生成买入单号**：
   - 调用 `generate_buy_order_no()` 函数
   - 根据交易日期查询或创建计数器记录
   - 格式：`NO{YYYYMMDD}{流水号:04d}`（例如：NO2024010100001）
   - 每天从0001开始递增，确保全局唯一性
2. 计算成交金额：`amount = price × shares`
3. 计算手续费：`fee = max(|amount| × fee_rate, min_fee)`
4. 计算净额：`net_amount = amount + fee`
5. 创建交易记录：
   - `buy_order_no = 生成的买入单号`
   - `trade_type = "buy"`
   - `remaining_shares = shares`（全部可卖）
   - `realized_profit = 0.0`（累计收益初始为0）
   - `single_profit = 0.0`
6. 更新或创建持仓（移动加权平均法）：
   - **已有持仓**: 
     - 总成本 = 原平均成本 × 原持仓 + 本次成交金额
     - 新持仓 = 原持仓 + 本次份额
     - 新平均成本 = 总成本 / 新持仓
     - 更新最新价格、市值、盈亏、盈亏率
   - **无持仓**: 创建新持仓记录

#### 3.1.2 加仓操作
**说明**: 
- 当前版本已取消独立的"加仓"概念
- 所有买入操作都创建新的买入记录，生成新的 `buy_order_no`
- 如需区分，可通过合约代码和交易日期进行筛选

---

### 3.2 卖出逻辑（网格交易模式）

#### 3.2.1 卖出交易处理
**触发条件**: `shares < 0` 且必须提供 `buy_order_no`

**核心特点**:
- ✅ 卖出必须指定基于哪笔买入记录（通过 `buy_order_no` 关联）
- ✅ 一笔买入可以对应多笔卖出（分批卖出）
- ✅ 单笔收益记录在卖出记录中，累计收益累加到买入记录
- ✅ 卖出数量不能超过该笔买入的 `remaining_shares`
- ✅ **网格交易核心优势**：通过不断高抛低吸，持仓成本会持续降低，理论上可以做到0成本

**处理流程**:
1. **验证输入**：
   - 检查是否提供 `buy_order_no`
   - 查询对应的买入记录
   - 验证卖出数量 ≤ 买入记录的 `remaining_shares`
2. 计算卖出数量：`sell_shares = |shares|`
3. 计算手续费：`fee = max(|amount| × fee_rate, min_fee)`
4. 计算单笔收益：
   ```
   single_profit = (卖出价 - 买入价) × 卖出数量 - 手续费
   ```
5. 创建卖出交易记录：
   - `contract = 买入记录的合约代码`（从买入记录获取）
   - `name = 买入记录的合约名称`（从买入记录获取）
   - `buy_order_no = 关联的买入单号`
   - `trade_type = "sell"`
   - `shares = -sell_shares`（负数）
   - `remaining_shares = 0`
   - `single_profit = 计算的单笔收益`
   - `realized_profit = 0.0`（卖出不需要累计收益）
6. **更新买入记录**：
   - `remaining_shares -= sell_shares`
   - `realized_profit += single_profit`（累加累计收益）
7. **更新持仓（成本摊薄算法）**：
   - 新持仓 = 原持仓 - 卖出数量
   - 如果持仓 > 0：
     - **关键逻辑**：扣除的是“卖出所得”而非“买入成本”，实现成本摊薄
     - 原总成本 = 平均成本 × (新持仓 + 卖出数量)
     - 卖出所得 = 卖出价 × 卖出数量
     - 新总成本 = 原总成本 - 卖出所得
     - 新平均成本 = 新总成本 / 新持仓
   - 如果持仓 = 0：平均成本归零
   - 更新最新价格 = 卖出价
   - 重新计算市值、盈亏、盈亏率

**示例说明**：
```
初始买入：1200股 @ 0.481元，总成本 = 577.2元
第一次卖出：1100股 @ 0.489元，卖出所得 = 537.9元

计算过程：
- 剩余持仓 = 1200 - 1100 = 100股
- 原总成本 = 577.2元
- 新总成本 = 577.2 - 537.9 = 39.3元
- 新平均成本 = 39.3 / 100 = 0.393元（成本从0.481降到0.393！）

效果：通过盈利卖出，持仓成本降低，实现了网格交易的核心优势。
```



### 3.3 删除交易逻辑

#### 3.3.1 删除买入记录
**前置条件**: 该买入记录不能有卖出记录

**处理流程**:
1. 检查是否有卖出记录关联该买入：
   - 查询 `buy_order_no` 相同且 `trade_type = "sell"` 的记录
   - 如果有卖出记录，禁止删除并提示用户（HTTP 400）
2. 如果没有卖出记录：
   - 从持仓中扣除该买入的份额
   - 重新计算平均成本（扣除对应的成交金额）
   - 更新现价为最后一笔交易的价格
   - 删除交易记录

#### 3.3.2 删除卖出记录
**说明**: 允许删除卖出记录，系统会自动恢复相关数据

**处理流程**:
1. **恢复买入记录**：
   - `remaining_shares += 卖出数量`（恢复可卖数量）
   - `realized_profit -= single_profit`（从累计收益中减去）
2. **恢复持仓**（反向操作卖出时的逻辑）：
   - `total_shares += 卖出数量`（恢复持仓数量）
   - **关键逻辑**：加回“卖出所得”而非“买入成本”
     - 当前总成本 = 平均成本 × 当前持仓
     - 卖出所得 = 卖出价 × 卖出数量
     - 原总成本 = 当前总成本 + 卖出所得
     - 新平均成本 = 原总成本 / 新持仓
   - 更新现价为最后一笔交易的价格
   - 重新计算市值、盈亏、盈亏率
3. 删除卖出记录

**示例**：
```
原始状态：
- 买入：1200股 @ 0.481元
- 卖出：1100股 @ 0.489元，收益 = 8.8元
- 剩余持仓：100股，成本 = 0.393元

删除卖出后：
- 买入 remaining_shares: 100 → 1200
- 买入 realized_profit: 8.8 → 0
- 持仓 total_shares: 100 → 1200
- 持仓 avg_cost: 0.393 → 0.481（恢复原成本）
```

### 3.4 持仓管理

#### 3.4.1 持仓重新计算机制

**核心原则**: 采用**全量重算**而非增量更新，确保数据准确性。

**触发时机**:
- ✅ 新增买入交易后
- ✅ 新增卖出交易后
- ✅ 删除买入记录后
- ✅ 删除卖出记录后
- ✅ 清仓操作后

**计算逻辑** (`recalculate_position` 函数):

1. **查询所有交易记录**：获取该合约的所有买入和卖出记录（按时间排序）

2. **分离买卖记录**：
   - `buy_trades` = 所有 `trade_type == "buy"` 的记录
   - `sell_trades` = 所有 `trade_type == "sell"` 的记录

3. **计算总买入/卖出**：
   ```python
   total_buy_shares = sum(t.shares for t in buy_trades)  # 买入为正数
   total_buy_amount = sum(t.amount for t in buy_trades)
   total_sell_shares = sum(abs(t.shares) for t in sell_trades)  # 卖出为负数，取绝对值
   total_sell_amount = sum(abs(t.amount) for t in sell_trades)  # amount也是负数，取绝对值
   ```

4. **计算持仓数量**：
   ```python
   position_shares = total_buy_shares - total_sell_shares
   ```
   - 如果 `position_shares <= 0`，删除持仓记录

5. **计算平均成本**：
   ```python
   net_cost = total_buy_amount - total_sell_amount  # 净成本
   avg_cost = net_cost / position_shares if position_shares > 0 else 0
   ```
   - **关键公式**：成本 = (买入金额 - 卖出金额) / 持仓
   - 体现网格交易的成本摊薄思想

6. **获取现价**：
   ```python
   latest_trade = all_trades[-1]  # 按时间排序的最后一条
   latest_price = latest_trade.price
   ```
   - **重要**：现价 = 最后一笔交易的价格（无论买入还是卖出）
   - 示例：如果最后交易是卖出 @ 0.489，则现价 = 0.489

7. **计算市值**：
   ```python
   market_value = position_shares * latest_price
   ```

8. **计算收益（已实现）**：
   ```python
   total_profit = sum(t.single_profit for t in sell_trades)
   ```
   - **重要**：profit 字段存储的是**已实现收益总和**
   - 即所有卖出记录的 single_profit 累加

9. **计算收益率（未实现）**：
   ```python
   unrealized_profit = (latest_price - avg_cost) * position_shares
   profit_rate = unrealized_profit / net_cost * 100 if net_cost > 0 else 0
   ```
   - **重要**：profit_rate 表示当前持仓的浮动盈亏相对于成本的百分比

10. **更新或创建持仓记录**：
    - 如果已有持仓：更新所有字段
    - 如果没有持仓：创建新记录

**优势**:
- ✅ 避免增量更新的累积误差
- ✅ 每次计算都基于真实数据
- ✅ 删除操作不会出现持仓错误
- ✅ 保证数据一致性

**示例验证**:
```
交易记录：
- 买入：1200股 @ 0.481元，金额 = 577.20元
- 卖出：1100股 @ 0.489元，金额 = 537.90元，single_profit = 8.60元

计算结果：
- 持仓 = 1200 - 1100 = 100股 ✅
- 净成本 = 577.20 - 537.90 = 39.30元
- 平均成本 = 39.30 / 100 = 0.393元 ✅
- 现价 = 0.489元（最后交易是卖出）✅
- 市值 = 100 × 0.489 = 48.90元
- 收益 = 8.60元（已实现）✅
- 未实现盈亏 = (0.489 - 0.393) × 100 = 9.60元
- 收益率 = 9.60 / 39.30 × 100 = 24.43%
```

#### 3.4.2 修改最新价格
**接口**: `PUT /api/positions/{position_id}?price={price}`

**处理流程**:
1. 更新 `latest_price`
2. 重新计算：
   - `market_value = total_shares × price`
   - `profit = (price - avg_cost) × total_shares`
   - `profit_rate = (price - avg_cost) / avg_cost × 100`

#### 3.4.3 一键清仓
**接口**: `POST /api/positions/{position_id}/clear`

**处理流程**:
1. 保存合约代码
2. 删除该合约所有交易记录
3. 调用 `recalculate_position()` 重新计算（会自动删除持仓记录）
4. 提交事务

## 四、API接口设计

### 4.1 交易记录接口

#### 4.1.1 获取所有交易记录
- **路径**: `GET /stock/api/trades`
- **参数**: `buy_order_no`（可选，搜索特定单号的买入及其所有卖出）
- **返回**: 
  - 默认：所有买入记录列表（按创建时间倒序），每条包含关联的卖出记录（sells数组）
  - 指定单号：该单号的买入记录及其所有卖出记录（按时间正序）

#### 4.1.2 创建交易记录
- **路径**: `POST /stock/api/trades`
- **请求体**:
  ```json
  {
    "contract": "512690",
    "name": "酒ETF",
    "price": 0.481,
    "shares": 1200,
    "fee_rate": 0.0002,
    "min_fee": 0.2
  }
  ```
  **卖出时请求体**:
  ```json
  {
    "contract": "",
    "name": "",
    "price": 0.500,
    "shares": -300,
    "fee_rate": 0.0002,
    "min_fee": 0.2,
    "buy_order_no": "NO2024010100001"
  }
  ```
- **返回**: `{ "status": "success", "trade_id": 1 }` 或 HTTP 错误状态码
- **说明**: 
  - 买入操作（shares > 0）会自动生成买入单号，交易日期默认为今天
  - 卖出操作（shares < 0）必须提供 `buy_order_no`，否则返回 HTTP 400
  - contract 和 name 在卖出时可为空，后端会从买入记录获取
  - trade_date 字段已废弃，后端自动使用当前日期

#### 4.1.3 获取指定合约的交易记录
- **路径**: `GET /stock/api/trades/{contract}`
- **返回**: 该合约的所有交易记录

#### 4.1.4 删除交易记录
- **路径**: `DELETE /stock/api/trades/{trade_id}`
- **返回**: 
  - 成功：HTTP 200 + `{ "status": "success" }`
  - 失败：HTTP 400/404 + `{ "detail": "错误信息" }`
- **说明**:
  - **删除买入记录**：如果该买入有卖出记录，返回 HTTP 400 禁止删除
  - **删除卖出记录**：允许删除，系统会自动恢复买入记录和持仓数据
  - 如果记录不存在，返回 HTTP 404

---

## 六、核心算法说明

### 6.1 买入单号生成算法

**方案**: 独立计数器表（方案A）

**函数**: `generate_buy_order_no(db, trade_date)`

**实现逻辑**:
```python
def generate_buy_order_no(db: Session, trade_date: str) -> str:
    # 将日期转换为YYYYMMDD格式
    date_str = trade_date.replace('-', '')
    
    # 查询当天的计数器记录
    counter = db.query(StockSerialCounter).filter(
        StockSerialCounter.counter_date == date_str
    ).first()
    
    if counter:
        # 已有记录，递增流水号
        counter.current_serial += 1
        serial_num = counter.current_serial
    else:
        # 新的一天，创建新记录，从1开始
        counter = StockSerialCounter(
            counter_date=date_str,
            current_serial=1
        )
        db.add(counter)
        serial_num = 1
    
    # 生成买入单号：NO + YYYYMMDD + 4位流水号
    buy_order_no = f"NO{date_str}{serial_num:04d}"
    return buy_order_no
```

**特点**:
- ✅ 每天从0001开始重新计数
- ✅ 全局唯一性保证（通过数据库唯一索引）
- ✅ 支持手动指定交易日期（补录历史交易）
- ✅ 并发安全（数据库事务保证）

**示例**:
- 2024年1月1日第1笔：`NO2024010100001`
- 2024年1月1日第2笔：`NO2024010100002`
- 2024年1月2日第1笔：`NO2024010200001`

### 6.2 手续费计算
```python
fee = max(|amount| × fee_rate, min_fee)
```
- 默认费率：0.0002（万分之二）
- 最低收费：0.2元

### 6.3 平均成本计算（买入）
```python
total_cost = avg_cost × total_shares + amount
new_total_shares = total_shares + shares
new_avg_cost = total_cost / new_total_shares
```

### 6.4 单笔收益计算（卖出）
```python
# 网格交易模式：基于特定买入记录
single_profit = (sell_price - buy_price) × sold_shares - fee
```
- 卖出价：本次卖出的价格
- 买入价：关联买入记录的买入价格
- 手续费：本次卖出的手续费（不分摊）

### 6.5 持仓成本摊薄算法（全量重算）

**核心逻辑**：采用全量重算，扣除“卖出所得”而非“买入成本”，实现成本持续降低

```python
def recalculate_position(db: Session, contract: str):
    # 1. 查询该合约的所有交易记录
    all_trades = db.query(StockTrade).filter(
        StockTrade.contract == contract
    ).order_by(StockTrade.created_at).all()
    
    # 2. 分离买入和卖出记录
    buy_trades = [t for t in all_trades if t.trade_type == "buy"]
    sell_trades = [t for t in all_trades if t.trade_type == "sell"]
    
    # 3. 计算总量
    total_buy_shares = sum(t.shares for t in buy_trades)
    total_buy_amount = sum(t.amount for t in buy_trades)
    total_sell_shares = sum(abs(t.shares) for t in sell_trades)
    total_sell_amount = sum(abs(t.amount) for t in sell_trades)
    
    # 4. 计算持仓
    position_shares = total_buy_shares - total_sell_shares
    
    if position_shares <= 0:
        # 持仓为零或负数，删除持仓记录
        db.query(StockPosition).filter(StockPosition.contract == contract).delete()
        return
    
    # 5. 计算成本：(买入金额 - 卖出金额) / 持仓
    net_cost = total_buy_amount - total_sell_amount
    avg_cost = net_cost / position_shares
    
    # 6. 获取现价（最后一笔交易的价格）
    latest_trade = all_trades[-1]
    latest_price = latest_trade.price
    
    # 7. 计算市值
    market_value = position_shares * latest_price
    
    # 8. 计算收益（所有卖出的 single_profit 汇总）
    total_profit = sum(t.single_profit for t in sell_trades)
    
    # 9. 计算未实现盈亏
    unrealized_profit = (latest_price - avg_cost) * position_shares
    
    # 10. 更新或创建持仓记录
    position = db.query(StockPosition).filter(StockPosition.contract == contract).first()
    if position:
        position.total_shares = position_shares
        position.avg_cost = avg_cost
        position.latest_price = latest_price
        position.market_value = market_value
        position.profit = total_profit  # 已实现收益
        position.profit_rate = unrealized_profit / net_cost * 100 if net_cost > 0 else 0
    else:
        # 创建新持仓记录...
```

**示例**：
```
买入：1200股 @ 0.481元，总成本 = 577.2元
卖出：1100股 @ 0.489元，卖出所得 = 537.9元

计算：
- 剩余持仓 = 1200 - 1100 = 100股
- 净成本 = 577.2 - 537.9 = 39.3元
- 新平均成本 = 39.3 / 100 = 0.393元
- 现价 = 0.489元（最后交易是卖出）
- 收益 = 8.60元（卖出的 single_profit）

效果：成本从 0.481 降到 0.393，实现了成本摊薄！
```

## 八、特殊场景处理

### 8.1 分批卖出
- 一笔买入可以对应多笔卖出（通过 buy_order_no 关联）
- 每次卖出不能超过该买入的 remaining_shares
- 单笔收益记录在卖出记录，累计收益累加到买入记录

### 8.2 删除有卖出的买入
- **禁止删除**：如果买入记录已有卖出记录，不允许删除
- 前端提示：“该买入记录已有 N 笔卖出，不能删除。请先删除所有关联的卖出记录。”
- 用户需先手动删除所有关联的卖出记录，才能删除买入记录

### 8.3 删除卖出记录
- **允许删除**：卖出记录可以随时删除
- **自动恢复**：系统会自动恢复以下数据：
  - 买入记录的 `remaining_shares`（剩余可卖数量）
  - 买入记录的 `realized_profit`（累计收益）
  - 持仓的 `total_shares`（持仓数量）
  - 持仓的 `avg_cost`（平均成本，通过加回卖出所得实现）
- **数据一致性**：删除后数据完全恢复到卖出前的状态

### 8.4 持仓为零
- 当 `position_shares <= 0` 时，自动删除持仓记录
- 不保留零持仓记录，保持数据库清洁

### 8.5 交易日期
- **已废弃手动指定交易日期功能**
- 后端自动使用当前日期作为交易日期
- 简化了用户操作流程
